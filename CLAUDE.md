# Контекст проекта

Хакатон HackAlem AI, трек «Финансы», кейс **«Граф денег»**. Команда Natural Intelligence, три человека.
Жёсткий дедлайн, работаем в одной ветке `main`.

**Задача:** по графу внутрибанковских переводов определить роли участников финансовой сети
и ранжировать их по приоритету проверки. Инструмент отвечает AML-аналитику на один вопрос:
**кого из 2 248 клиентов смотреть первым и почему.**

Полный план — [docs/PLAN.md](docs/PLAN.md). Деление работ — [docs/ROLES.md](docs/ROLES.md).
Техзадание — [docs/ТЗ-граф-денег.md](docs/ТЗ-граф-денег.md).

## Кто что делает — ЧИТАТЬ ПЕРЕД ЛЮБОЙ ПРАВКОЙ

Три человека пушат в один `main`. Это безопасно **только** при жёстком владении файлами.

| Владелец | Файлы | Персональный план |
|---|---|---|
| **kuanyshs** | `src/schema.py`, `src/io.py`, `src/features.py`, `src/roles.py`, `src/clusters.py`, `src/priority.py`, `src/mock.py`, `run.py`, `requirements.txt` | [docs/TASK-kuanyshs.md](docs/TASK-kuanyshs.md) |
| **olzhasraiganiyev04-sketch** | `app.py`, `web/**`, `src/viz.py` | [docs/TASK-olzhas.md](docs/TASK-olzhas.md) |
| **narekdavtyan228-svg** | `src/agent.py`, `src/tools.py`, `README.md`, `docs/**` | [docs/TASK-narek.md](docs/TASK-narek.md) |

**Правило без исключений: чужой файл не редактируем.** Нужна правка в чужом файле —
пишем владельцу в чат команды. Иначе его следующий пуш затрёт вашу работу или вы получите
конфликт посреди хакатона.

Если ты — Claude Code и тебя просят изменить файл вне зоны владения текущего пользователя:
**остановись и скажи об этом**, предложи написать владельцу.

## Git: как работать втроём в одной ветке

```bash
# перед началом работы и перед КАЖДЫМ пушем
git pull --rebase origin main

# обычный цикл, каждые 15-20 минут
git add <только свои файлы>
git commit -m "краткое описание"
git pull --rebase origin main
git push origin main
```

- **Всегда `--rebase`.** Без него получим мусорные merge-коммиты и конфликты на ровном месте.
- **`git add` только своих файлов**, не `git add -A` вслепую — иначе утащите чужую незакоммиченную работу.
- **Пушим часто, мелкими коммитами.** Чем реже пуш, тем больнее конфликт.
- **`out/` в `.gitignore` — выгрузки не коммитим.** Три человека, генерирующие одни и те же CSV,
  конфликтовали бы на каждом пуше.
- **`.env` в `.gitignore` — ключи никогда не коммитим.**

Если словили конфликт: `git status` покажет файлы. Если конфликт в **чужом** файле — почти всегда
правильное действие `git checkout --theirs <файл>` (взять версию владельца), потому что вы его
трогать не должны были.

## Контракт выгрузок — менять только по общему согласию

Схема зафиксирована в ТЗ, жюри проверяет её механически. Лежит в `src/schema.py`:

```python
NODES_ROLES_COLUMNS = ["gid", "role", "role_score", "cluster_id", "priority_score", "evidence"]
CLUSTERS_COLUMNS    = ["cluster_id", "n_nodes", "n_seed", "sum_kzt_internal", "top_gids", "hypothesis"]
TOP_NODES_COLUMNS   = ["rank", "gid", "role", "priority_score", "why"]
ROLES = ["consolidator", "transit", "distributor", "terminal",
         "terminal_unknown", "coordinator", "peripheral"]
```

`python run.py` в конце сам прогоняет `schema.validate()` — ровно те проверки, что сделает жюри:
2248 строк, роли из словаря, `evidence` непустой и ≤200 символов, скоры в [0,1], `cluster_id` у всех.

Лишние колонки добавлять можно. Обязательные удалять — нет.

## Проверенные факты по данным

Посчитаны на реальных файлах. Deep-research отчёты в `deep-research/` рассуждали по README
датасета, **не по данным**, и в двух местах ошибаются. Верить нужно этой таблице.

| Факт | Значение |
|---|---|
| Узлы / рёбра / транзакции / seed | 2248 / 3119 / 4840 / 81 |
| Оборот | 365 890 012 KZT |
| Узлов без исходящих | 1554, из них depth≤3 — **1110**, depth=4 — **444** |
| Узлов-сирот (нет ни в одном ребре) | 19, все seed |
| max out_deg / max in_deg | 116 / 24 |
| Взаимные пары A↔B | 177 |
| Простых циклов ≤6 / ≤8 | 1541 / 8335 (счёт 0.12 с) |
| Слабосвязных компонент | 35 |
| Узлов, отдающих больше, чем получили (не-seed) | 335, разрыв 229.9 млн = **62.8% оборота** |
| `transit_ratio ≥ 0.8` | 78 узлов |
| Отправили раньше, чем получили | 302 узла |
| Полный расчёт всех метрик | ≈1.4 с (лимит ТЗ — 5 минут) |

**Три опровержения ресёрча:**

1. `depth` в данных — **ровно BFS-дистанция от ближайшего seed**, максимум 4. Утверждение
   «пути доходят до 15 шагов» неверно, 15 — это максимум `n_seeds_upstream`.
2. `n_seeds_upstream` **почти не ранжирует**: 1134 узла имеют ровно 7, 563 узла ровно 1.
   Годится как фильтр (≥2), не как основа приоритета.
3. `taint_share` разделяет слабо — среднее 0.752, у 888 узлов выше 0.9. Причина структурная:
   граф построен обходом от seed, поэтому почти всё в нём ниже по течению от фигурантов.
   Полезно **дополнение** `external_share = 1 − taint_share` — доля денег извне выборки.

## Ограничения данных, которые нельзя игнорировать

Они объявлены в ТЗ заранее, и **их учёт оценивается**:

- Видны **только исходящие** переводы. Входящие извне выборки не видны, полный баланс узла
  посчитать нельзя.
- У **seed занижен `in_kzt`** — граф собран от них. Отношение «отдал/получил» у seed некорректно.
- **444 узла на 4-м колене** без исходящих — артефакт обрыва обхода, а не «деньги осели».
  Отсюда отдельная роль `terminal_unknown`.
- **Порог 5 000 KZT**: дробление ниже порога невидимо в принципе. Гипотезы о нём —
  только с явной пометкой «спекулятивно».
- **Нет атрибутов клиента и нет ground truth.** Оценка идёт по обоснованности критериев,
  а не по accuracy.

## Что запрещено по ТЗ

- **Хардкодить результат** — зашитые списки gid вместо расчёта.
- **Чёрный ящик** — роль без объяснимого правила не засчитывается. Никаких эмбеддингов,
  GNN, struc2vec: `evidence` из 128-мерного вектора объяснить нельзя.
- **Внешние данные и выдуманные атрибуты** клиентов (пол, возраст, доход, организация).
- **GPU, облако, платные сервисы** для воспроизведения.
- Пересчёт дольше **5 минут** (сейчас 1.1 с, запас стократный).

## Как формулируем выводы

Только как **гипотезы для проверки**: «признаки консолидации», «требует запроса входящих».
Никогда — как утверждение о виновности. Это прямое требование ТЗ.

## Соглашения по коду

- Комментарии, докстринги, текст интерфейса и README — **по-русски**. Жюри русскоязычное.
- В `evidence` и `why` — **обязательно числа**. «Высокий скор» не принимается.
- Пороги — **перцентили нашего распределения**, не константы из статей. Каждый порог
  надо уметь объяснить жюри за минуту.
- Новая зависимость — только через владельца `requirements.txt` (kuanyshs). Чем меньше
  зависимостей, тем выше шанс, что у жюри всё запустится: это 25 баллов.
- Никакого `npm`. React и Cytoscape подключаются с CDN.

## Секреты

Ключ LLM берётся **только** из переменной окружения `DEEPSEEK_API_KEY`.
Локально: скопировать `.env.example` в `.env` и вписать туда. В код не вписываем никогда.

Модель `deepseek-flash`, база `https://api.deepseek.com`, формат OpenAI `/chat/completions`.
Tool-calling работает. **В системном промпте обязательно требовать русский язык** —
иначе на русский вопрос модель отвечает по-английски.

## Что оценивает жюри

| Критерий | Баллы |
|---|---|
| Соответствие задаче и работоспособность | 25 |
| Техническая реализация | 25 |
| **README и воспроизводимость** | **25** |
| Ценность и применимость | 15 |
| Потенциал и оригинальность | 10 |

README весит столько же, сколько весь код. Пять must-have из ТЗ: воспроизводимый пайплайн,
роль и скор у каждого узла, **объяснимые критерии** (жюри назовёт 3 случайных gid и попросит
объяснить роль за минуту), кластеризация, топ-лист **и визуализация с поиском по gid**.
