## 1:20 – 2:50 · Схема сети и топ-лист

```bash
python app.py     # http://localhost:8000
```

1. **Схема.** Цвет — роль, размер — приоритет проверки, стрелки — направление денег.
   > «Рисуем топ-300 по приоритету и их окружение. Все 2 248 сразу — это каша,
   > в которой ничего не видно. Остальные доступны поиском.»

2. **Поиск по gid.** Попросить жюри назвать любой gid из `nodes_roles.csv` и найти его
   при них. Это проверяют почти наверняка.

3. **Топ-лист.** Открыть таблицу.
   > «Очередь проверки. В топ-25 — 16 координаторов, 7 распределителей и 2 периферийных узла.
   > Колонка справа объясняет каждую строку числами, а не оценкой риска.»

4. **Проверка, что топ-лист осмыслен** — 15 секунд, говорить сразу за топ-листом:
   > «Как мы знаем, что это правильные узлы, а не просто крупные обороты? Изымаем из графа
   > пять первых узлов топа — сеть рассыпается со 16 компонент до **171**. Изымаем пять
   > случайных — получаем **16.6**, то есть не меняется ничего. Разрыв в десять раз
   > на пяти счетах из двух с половиной тысяч.»

   Это опциональный пункт ТЗ и сильный аргумент: приоритет собран из потоков и происхождения
   денег, про связность он ничего не знает, поэтому совпадение — независимая проверка.
   Цифры в `out/resilience.csv` и в README §9.

Если спросят про роли — показать таблицу порогов в README и сказать главное:

> «Пороги заданы числами, а не перцентилями. На этом графе медиана входящей степени
> равна единице, поэтому P90 даёт порог 2 и правило пропускает почти всех подряд.
> Мы взяли 4 плательщика для консолидатора — это верхние три процента.»

## 3:50 – 4:30 · Ассистент

Взять пять gid из топ-листа, задать вопрос из условия задачи:

> «Кто собирает деньги с этих пятерых?»

Ответ придёт за 6–18 секунд, если работает модель, и мгновенно в шаблонном режиме.
**Не молчать в это время** — проговаривать, что происходит:

> «Ассистент сейчас вызывает те же функции, что и интерфейс, и собирает ответ только
> из их вывода.»

Когда ответ появится, прочитать вслух одну строку и подчеркнуть:

> «Каждое число здесь взято из выгрузок, ассистенту запрещено считать в уме.
> Он обязан называть gid, на которые опирается, и формулирует выводы как гипотезы.»

**Если нет интернета или ключа** — ничего не менять, ассистент сам переходит на шаблоны
поверх тех же восьми функций. Но под ответом в панели загорается подпись
**«шаблонный режим, без LLM»** — жюри её увидит. Поэтому не ждать вопроса, а сказать самому:

> «Обратите внимание на подпись под ответом: сейчас работает шаблонный режим, без обращения
> к модели. Это не поломка — так задумано. Демо не должно зависеть от вайфая в зале,
> поэтому те же восемь функций обслуживают вопрос и без ключа. С ключом отвечает модель,
> данные под ответом те же самые.»

Проговаривать это спокойно и не извиняясь: устойчивость к отсутствию сети — плюс решения,
а не оправдание.

## Вопросы, которые зададут почти наверняка

| Вопрос | Короткий ответ |
|---|---|
| Назовите три случайных gid и объясните роль | Поиск → карточка → колонка `evidence`, там числа и сработавший порог |
| Почему такие пороги | Числа, а не перцентили: медиана `in_deg` = 1, P90 вырождается в 2. См. README §4 |
| Почему не нейросеть | Обоснование роли из 128-мерного вектора не объяснить, а объяснимость — обязательное требование |
| Как масштабируется на миллион | README §13: графовая БД, инкрементальный пересчёт, taint батчами по компонентам. Правила ролей не меняются — они локальные |
| Чем проверяли без разметки | `python validate_injection.py` — внедряем синтетические fan-in / fan-out / цепочку / цикл и меряем, поднимает ли их пайплайн. Все четыре типа опознаются на 100%, Recall@300 = 0.59. См. README §8 |
| Почему Recall@50 всего 0.09 | Синтетика оперирует суммами 2–4 млн, а верх топа занят узлами с разрывом 22 млн — приоритет отдаёт им предпочтение правильно |
| Что будет, если изъять топ-N | `out/resilience.csv`: топ-5 рвут сеть на 171 компоненту против 16.6 при случайном изъятии, 117 счетов в полной изоляции. README §9 |
| Чем мотивы лучше обычных метрик | Метрика даёт число, мотив даёт проверяемый факт. Два отправителя на 67 и 82 счёта имеют 19 общих получателей; случайно ожидается 4.1, за 2000 прогонов 19 не выпало ни разу, z = 7.9. README §5 |
| Не артефакт ли это больших степеней | Прямо да, отчасти — поэтому и считается z-скор относительно случайной модели с теми же степенями. Без базиса совпадение ничего не доказывает. README §5, последний абзац |
| Как ищете аномалии | Забор Q3 + 3·IQR **внутри колена обхода**: узел с 60 получателями на 1-м колене — норма, на 4-м — выброс. 94 узла, 4.2%. IsolationForest не взяли: он даёт число, а не объяснение. README §6 |
| Каких данных не хватает | Не список претензий, а колонка `next_request` у каждого узла: 444 запросить исходящие, 179 входящие, 101 переводы ниже порога, 1524 ничего не нужно. В топ-25 — 19 узлов требуют входящих. README §11 |
| Что такое `terminal_unknown` | Документированное расширение словаря: 444 узла обрыва обхода отделены от 1 091 настоящего стока |

## Как репетировать

Прочитать вслух с секундомером **три раза подряд**. Не про себя — вслух: про себя текст
всегда идёт быстрее, и на защите появляется лишняя минута, которой нет.

Замер по тексту: в репликах 501 слово. При темпе 140 слов в минуту это 3 минуты 33 секунды,
при спокойных 120 — **4 минуты 09 секунд**. Плюс прогон пайплайна, клики и паузы.

**Сценарий стал плотным — в пять минут он укладывается только при темпе от 140 слов
в минуту.** Поэтому репетиция с секундомером обязательна, а не желательна: если первый
прогон вслух дал больше 4:30, резать нужно заранее, а не на сцене.

**Порядок сокращения:**

1. Реплика про пороги в блоке 1:20–2:50 — она всё равно есть в README, и её спросят отдельно.
2. Комментарий к схеме («рисуем топ-300...») — сократить до одной фразы.
3. Вставка про устойчивость — убрать из речи, оставить как ответ на вопрос.

**Не режется никогда:** разбор узла и блок про границы. На первом держится впечатление,
на втором — доверие.
