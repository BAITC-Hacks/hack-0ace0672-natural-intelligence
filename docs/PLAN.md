# План решения: «Граф денег»

Команда Natural Intelligence · трек «Финансы» · HackAlem AI

**Ограничение:** ~2 ч 45 мин, трое. Всё, что не помещается, режется по порядку из раздела 15.

---

## 1. Что мы строим

Пайплайн, который из трёх parquet-файлов восстанавливает роли участников платёжной сети,
ранжирует их по приоритету проверки и отдаёт аналитику веб-интерфейс со схемой сети
и AI-ассистентом.

Один вопрос, на который отвечает всё решение: **кого из 2 248 клиентов смотреть первым и почему.**

Артефакты: `out/nodes_roles.csv`, `out/clusters.csv`, `out/top_nodes.csv`, веб-экран, README, схема, демо.

## 2. Факты по данным — проверены на реальных файлах

Оба deep research рассуждали по README, а не по данным. Мы посчитали. Числа ниже — подтверждённые,
на них можно строить правила и ссылаться перед жюри.

| Факт | Значение |
|---|---|
| Узлы / рёбра / транзакции / seed | 2248 / 3119 / 4840 / 81 |
| Оборот | 365 890 012 KZT |
| Узлов без исходящих | **1554**, из них depth≤3 — **1110**, depth=4 — **444** |
| Узлов с входом и выходом | 671 |
| Узлов-сирот (нет ни в одном ребре) | 19, **все seed** |
| max out_deg / max in_deg | 116 / 24 |
| Взаимные пары A↔B | 177 |
| Простых циклов ≤6 / ≤8 | 1541 / 8335, счёт 0.12 с |
| Слабосвязных компонент | 35 (1877, 270, 17, 13, 6, …, + 19 одиночек) |
| `external_funding_gap > 0` у не-seed | 335 узлов, **229.9 млн = 62.8% оборота** |
| `transit_ratio ≥ 0.8` | 78 узлов (старый `pass_through` в [0.8, 1.2] — 72) |
| Отправили раньше, чем получили | 302 узла |
| Медианная задержка вход→выход ≤1 дня | 292 узла |
| Рёбер с `n_tx ≥ 10` / max `n_tx` | 29 / 67 |
| Событий (получатель, дата) с ≥3 отправителями | 66, максимум 7 отправителей |
| Медиана / max суммы транзакции | 30 000 / 3 000 000 KZT |
| **Полный расчёт всех метрик** | **≈1.4 с** — лимит ТЗ в 5 минут не связывает |

### Три опровержения, которые важнее подтверждений

1. **`depth` — это ровно BFS-дистанция от ближайшего seed.** Максимум 4, расхождений ноль.
   Утверждение «пути доходят до 15 шагов» неверно — 15 это максимум `n_seeds_upstream`,
   признаки перепутаны. В презентации слайд 11 надо исправить.
2. **`n_seeds_upstream` почти не ранжирует.** 1134 узла имеют ровно 7, 563 узла ровно 1.
   Годится как фильтр «≥2 seed», не годится как основа приоритета.
3. **Переход с `pass_through` на `transit_ratio` даёт +6 узлов** (72→78). Метрику берём — она
   не взрывается на seed, — но как «прорыв» не продаём.

## 4. Признаки узла

Все считаются за ~1.5 с. Пишутся в `nodes_roles.csv` дополнительными колонками — ТЗ это разрешает.

| Признак | Формула | Смысл |
|---|---|---|
| `in_deg`, `out_deg` | число разных контрагентов | база |
| `in_kzt`, `out_kzt`, `in_tx`, `out_tx` | суммы и количества | база |
| `transit_ratio` | `min(in_kzt, out_kzt) / max(in_kzt, out_kzt)` | ограничен [0,1], не взрывается на seed |
| `net_flow` | `(in_kzt − out_kzt) / (in_kzt + out_kzt)` | знак: >0 копит, <0 раздаёт |
| `external_funding_gap` | `out_kzt − in_kzt` | точки вливания денег извне выборки |
| `was_expanded` | `depth ≤ 3` | обход разворачивал узел и исходящих не нашёл |
| `taint_share` | haircut-трассировка от 81 seed | доля оборота, пришедшая от фигурантов |
| `ppr` | personalized PageRank, рестарт на seed, вес `sum_kzt` | куда стекаются деньги фигурантов |
| `n_seeds_upstream` | обратная достижимость по направленным рёбрам | **фильтр ≥2**, не ранжирование |
| `hhi_in`, `hhi_out` | Херфиндаль по долям контрагентов | концентрация: высокий = воронка |
| `median_delay_days` | медиана дней между входящим и следующим исходящим | транзит, подтверждённый временем |
| `sent_before_received` | первый out раньше первого in | признак внешнего финансирования |
| `max_edge_n_tx` | max `n_tx` по инцидентным рёбрам | видимая часть дробления |
| `sync_in_events` | число дат, когда ≥3 разных отправителя в один день | синхронные переводы |
| `in_cycle_le6` | входит ли в простой цикл длиной ≤6 | возвратные потоки |

### Haircut-taint — 30 строк, ядро нашего подхода

Каждому seed даём taint = 1.0. Идём по графу в топологическом порядке (циклы — итеративно,
5–10 проходов до сходимости). Узел получает
`taint_in = Σ(taint(u) × sum_kzt(u→v)) / in_kzt(v)` и передаёт его дальше пропорционально исходящим.

Это прямой ответ на вопрос сценария ТЗ: «чьи это деньги». Узел с 99 получателями и taint 0.09 —
внешний бизнес, куда обход случайно зашёл. Узел с 61 получателем и taint 0.53 — распределитель
денег группы. Степени этого не различают.

## 5. Правила ролей

Пороги — **перцентили нашего распределения**, а не литературные константы. Правила проверяются
сверху вниз, первое совпадение выигрывает.

| # | Роль | Условие | Ожидаемо узлов |
|---|---|---|---|
| 1 | `peripheral` | нет ни одного ребра (сироты) | 19 |
| 2 | `terminal_unknown` | `out_deg = 0` и `depth = 4` | 444 |
| 3 | `terminal` | `out_deg = 0` и `was_expanded` | ~1090 |
| 4 | `transit` | `in, out > 0` и `transit_ratio ≥ 0.8` | ~78 |
| 5 | `distributor` | `out_deg ≥ P90` и `net_flow < −0.3` и `hhi_out < 0.3` | ~60 |
| 6 | `consolidator` | `in_deg ≥ P90` и `net_flow > 0.3` | ~25 |
| 7 | `coordinator` | `n_seeds_upstream ≥ 2` и `out_deg ≥ 5` и `taint_share ≥ P75` и ≥2 соседа с ролью consolidator/distributor | ~33 |
| 8 | `peripheral` | всё остальное | ~500 |

`terminal_unknown` — расширение словаря ТЗ, оно разрешено при условии документирования.
Именно оно закрывает опциональный пункт «учёт артефакта обрыва графа»: **1110 настоящих стоков
против 444 неизвестных**, а не «444 артефакта», как пишет ресёрч.

### role_score

```
role_score = sigmoid(k · (feature − threshold)) × (1 − artefact_penalty)
```

`artefact_penalty`: 0.4 для `depth = 4` (искусственный terminal), 0.3 для seed (входящие занижены
по построению), 0 иначе. Это даёт готовый ответ жюри на вопрос «почему уверенность 0.4, а не 0.9»
и превращает скор из декорации в аргумент.

### evidence

До 200 символов, обязательно с числами. Шаблон на роль, подстановка значений:

> `получил 12.4 млн от 47 отправителей, отдал 12.1 млн троим за 2 дня, transit_ratio 0.98, taint 0.71`

## 6. Кластеризация

1. **35 слабосвязных компонент** — бесплатная и честная структура, отдаём как есть.
2. **Louvain внутри компоненты на 1877 узлов**, на неориентированной проекции,
   с явной оговоркой в README (стартовый код это прямо разрешает).
3. Гипотеза кластера генерируется из **состава ролей и taint**, а не из фантазии:
   - много `consolidator` + много `peripheral` → признаки воронки и дробления;
   - цепочки `transit` с высоким `taint_share` → признаки многошагового прогона;
   - наличие циклов → признаки возвратных потоков.

Формулировки — только как гипотезы. ТЗ отдельно требует «признаки консолидации»,
а не «преступная группа».

## 7. priority_score

Композит, нормированный в [0, 1]:

```
priority = 0.30 · norm(taint_share × out_kzt)      # сколько денег группы через узел прошло
         + 0.25 · norm(external_funding_gap)        # точка вливания извне
         + 0.20 · norm(ppr)                         # куда стекаются деньги фигурантов
         + 0.15 · transit_purity                    # transit_ratio × (задержка ≤ 2 дней)
         + 0.10 · norm(n_seeds_upstream)            # сколько фигурантов выше по течению
```

Веса — наши, обосновываются в README. Каждое слагаемое интерпретируемо отдельно,
поэтому топ-лист защищаем по компонентам, а не «модель так решила».

## 9. Интерфейс: React + Cytoscape.js

**Без npm-сборки.** React 18 и Babel подключаются с CDN, весь фронт — один `web/index.html`.
Причина: 25 баллов за воспроизводимость. `npm install` на чужой машине — лотерея, `pip install` — нет.

| Слой | Выбор | Почему |
|---|---|---|
| Сервер | FastAPI + uvicorn | ключ DeepSeek остаётся на бэке, в браузер не попадает |
| UI | React 18 через CDN + Babel standalone | ноль сборки, открывается сразу |
| Граф | Cytoscape.js + layout `fcose` | направленные рёбра, стрелки, программный поиск и подсветка |
| Fallback | `out/graph.html` на pyvis | если сервер не поднялся — must-have №5 всё равно закрыт |

### Экраны

1. **Схема сети.** Направление потоков стрелками, цвет = роль, размер = `priority_score`,
   толщина ребра = `sum_kzt`. По умолчанию рисуем топ-300 по приоритету плюс их соседей —
   2248 узлов сразу превратятся в кашу и будут тормозить.
2. **Поиск по gid — обязателен.** Жюри назовёт gid и попросит найти. Поле ввода → узел
   подсвечивается, камера центрируется, разворачивается его окружение на одно колено.
3. **Карточка узла.** Роль, `role_score`, `evidence`, ключевые числа, топ-контрагенты,
   кнопка «спросить ассистента про этот узел».
4. **Топ-лист.** Таблица из `top_nodes.csv`, клик по строке → узел на схеме.
5. **Чат с ассистентом** — панель сбоку, §10.

### API

```
GET  /api/graph?top=300        узлы и рёбра для отрисовки
GET  /api/node/{gid}           карточка + соседи
GET  /api/top                  топ-лист
GET  /api/clusters             кластеры
POST /api/ask                  {question} -> {answer, cited_gids[]}
```

## 10. AI-ассистент

**Модель:** `deepseek-flash` (DeepSeek-V4.1-Flash), эндпоинт `https://api.deepseek.com`,
OpenAI-совместимый `/chat/completions`. Tool-calling проверен на живом ключе: работает,
латентность ~1.1 с.

**Ключ — только через переменную окружения `DEEPSEEK_API_KEY`.** В репозиторий кладём
`.env.example` с пустым значением, `.env` — в `.gitignore`. Ключ в коде = утечка в историю git.

**Системный промпт обязан требовать русский язык** — на русский вопрос без явного указания
модель отвечает по-английски, проверено.

### Инструменты (обычные функции на pandas)

| Инструмент | Назначение |
|---|---|
| `get_node(gid)` | карточка узла: роль, признаки, evidence |
| `who_collects_from(gids[])` | общие получатели ниже по течению от указанных узлов |
| `trace_path(src, dst, max_len)` | путь движения денег между узлами |
| `top_nodes(role?, cluster_id?, n)` | топ по приоритету с фильтрами |
| `cluster_summary(cluster_id)` | состав ролей, оборот, seed, гипотеза |
| `find_nodes(filters)` | отбор по признакам: «taint > 0.8 и out_deg > 20» |

Сценарий из ТЗ «кто собирает деньги с этих пятерых?» ложится на `who_collects_from` напрямую.

**Жёсткое правило:** ассистент отвечает **только** числами из выгрузок и **обязан** называть gid,
на которые опирается. Никаких рассуждений «от себя» — ТЗ запрещает чёрный ящик,
а галлюцинация на демо стоит дороже, чем отсутствие ассистента.

**Фолбэк:** нет ключа или нет сети → те же вопросы обслуживаются шаблонными ответами
поверх тех же функций. Демо не должно зависеть от вайфая в зале.

## 11. Валидация без ground truth

**Planted-pattern injection.** Вставляем в граф синтетические fan-in / fan-out / цепочку / цикл
на ~2% узлов, прогоняем пайплайн, меряем, насколько высоко он их ранжирует:
**Recall@K и Precision@K при K = 50 / 100 / 300.**

Это единственный честный ответ на «проверять не с чем», делается за 30–40 минут
и почти наверняка не будет ни у одной другой команды. Прямое попадание в 10 баллов за оригинальность.

**Санитарная проверка топа:** если больше 30% топ-узлов — это seed или `depth = 4`,
значит ранжирование поймало артефакт выгрузки, а не структуру. Порог, меняющий решение.

## 16. Что не делаем принципиально

- `betweenness` — 1554 узла без исходящих, у большинства ноль, у остальных искажена усечением.
- Эмбеддинги, GNN, struc2vec, RolX — `evidence` из 128-мерного вектора не объяснить,
  а must-have №3 требует именно этого.
- Neo4j как движок — только абзац в разделе масштабирования.
- Вендорские цифры и регуляторика (SR 11-7, EU AI Act) — по одной строке в README.
  Здесь жюри с рубрикой, а не регулятор.
- `simple_cycles` без `length_bound` — граф не DAG.

## 18. Демо, 5 минут
